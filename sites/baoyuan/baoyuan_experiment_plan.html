Why Iterative Blind Testing?

Baoyuan has no live Main Grid meter — closed-loop optimisation is not possible in real time. Instead, Agent 2 operates in open-loop experiment mode: it sweeps a controlled input variable over a fixed period, records all observable outputs, then waits for Baoyuan to provide the Main Grid CSV after the period ends. The CSV is imported and correlated with experiment data to determine the optimal HyESys setpoint. Each period refines the model for the next period.

Safety Rules

BMS Voltage Protection

  • Trigger: singleVoltageAvg < 3.20 V
  • Action: Pause experiment, send charge command −10 kW/phase
  • Hold: BMS charging continues, kVAr sweep paused
  • Resume: singleVoltageAvg ≥ 3.45 V → restore last kVAr step, send 0 kW/phase
  • Hysteresis: 3.20 V pause ↔ 3.45 V resume (0.25 V band prevents cycling)

PCS Temperature Cap

  • Trigger: temperature ≥ 83°C
  • Action: Snapshot current |kW| + |kVAr| → set as hard output cap
  • Effect: No command issued above this cap until temperature clears
  • Note: Cotton contamination from production environment blocks fans — clean with compressed air periodically

Phase-Level Hard Limit

  • Enforced in _issue_command() before every MQTT publish
  • Formula: headroom = max(0, 40.0 − |kW_per_phase|)
  • If |kVAr_per_phase| > headroom → clamp kVAr to headroom, log warning
  • At rated capacity (120 kVAr, 0 kW): each phase = 40 kVAr + 0 kW = 40 ✓ exactly at limit

Why CapBank currents? They are the only real-time observable electrical measurement at MSB1. Voltage, kW, kVAr, and PF on the CapBank meters always read zero — the hardware only measures current. CapBank current reduction is therefore the primary live proxy for HyESys effectiveness until the Main Grid CSV arrives.

Post-Experiment Follow-Up Steps

  1. 1

    Auto-Zero on Experiment Completion

    When Agent 2 detects that all 120 steps have been completed, it automatically issues a final command of 0 kVAr / 0 kW to all three phases, returning HyESys to a neutral state.

  2. 2

    Request Main Grid History CSV from Baoyuan

    Jason contacts the Baoyuan site contact and requests the Main Grid electricity consumption data for the experiment period — typically a 15-minute interval kW/kWh/PF CSV export from their energy meter or utility portal.

  3. 3

    Import Main Grid CSV

    Run sites/baoyuan/import_maingrid.py to ingest the CSV into the maingrid_history table in baoyuan.db. The script aligns timestamps to the experiment period and normalises units.

  4. 4

    Correlation Analysis via site_agent.py

    Run site_agent.py in analysis mode. It cross-references three data sources:

    • HyESys kVAr setpoint per step (experiment_log)
    • CapBank current response per step (meter_records)
    • Main Grid kW / PF per interval (maingrid_history)

    Output: optimal kVAr setpoint → minimum Main Grid kW curve, and the knee-point beyond which further injection yields diminishing returns.

  5. 5

    Propose Next Period Configuration

    site_agent.py compiles a Telegram message to Jason summarising findings and proposing the operating setpoint for the next test period. Proposal includes:

    • Recommended kVAr setpoint (identified knee-point)
    • Expected current reduction and savings estimate
    • Experiment mode for next period (fixed setpoint validation or refined sweep)
  6. 6

    Jason Approves → Next Period Begins

    Jason reviews the proposal and approves via Telegram reply. Agent 2 loads the new configuration and begins the next experiment period. After 2–3 such cycles, the system transitions from sweep mode to a validated fixed-setpoint operating configuration.
